appstore-release-kit

Release scripts for App Store Connect. Node ≥ 20, one API key, zero dependencies. Every write is read back from the API before the command reports success, because a 2xx from App Store Connect is not the same as the change having taken.

Why this exists

A 1.0 sat on build 30 for three weeks while builds 31 through 36 came and went, each one "uploaded successfully" — uploading a build does not put it on the version, and neither xcodebuild -exportArchive nor Transporter tells you that. The build that finally went to review was rejected under 3.1.2 because two links on the paywall "did nothing"; the resubmission carried a capture taken right after tapping each link, with Safari open and "◀ App" in the status bar, and passed. The scripts are what came out of those two weeks, extracted from two apps in production. Everything here has shipped a real build.

Four commands

npx -p appstore-release-kit wait-for-build <appId> <build>
Polls until the build leaves PROCESSING, answers export compliance, reads the flag back. If the build goes INVALID, this is where the reason shows up.
npx -p appstore-release-kit attach-build <versionId> [build]
Attaches a VALID build to a version record and reads the relationship back. With no build number it just prints which build the version carries right now — the cheap pre-submission check. Never submits.
npx -p appstore-release-kit subscription-screenshot state|upload <groupId> [png]
The review screenshot every subscription needs before it leaves MISSING_METADATA. It is in the API, despite the folklore. state prints what App Store Connect itself says is missing.
npx -p appstore-release-kit review-attachment state|upload|delete <reviewDetailId> [file]
Attaches a file to App Review, next to the review notes. Notes are text only; proof that a control works goes here. One attachment per review — composite several captures into one image.

Setup: an App Store Connect API key (role App Manager) in ~/.appstoreconnect/private_keys/, plus ASC_KEY_ID and ASC_ISSUER_ID in the environment. Run any command without arguments for usage. Full README on GitHub.
